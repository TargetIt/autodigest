# autodigest

`autodigest` 是一个用于学习复杂概念的自动消化仓库。

它的目标不是简单存资料，而是把复杂材料加工成你自己的结构化理解，并默认输出中文内容。

核心动作：

1. 收集原始材料。
2. 明确待消化对象。
3. 抽取事实、概念、机制、例子和疑问。
4. 按多个认知视角重新解释同一个对象。
5. 产出几篇可复用的中文文章。

## 仓库结构

```text
autodigest/
  inbox/       临时材料、链接、摘录、想法。
  sources/     书、论文、视频、文档、代码、课程等源材料记录。
  digests/     对单个知识单元的消化笔记。
  concepts/    可复用概念页、定义、模型、区分。
  outputs/     最终产出：文章、学习指南、图解、演讲稿等。
  prompts/     AI 辅助消化提示词。
  scripts/     小型本地自动化脚本。
  templates/   中文 Markdown 模板。
  workflows/   固定 Auto Digest 工作流。
```

## Auto Digest 工作流

当你说“使用 Auto Digest 消化某个复杂概念”时，默认按这个流程处理：

1. 定义待消化对象。
2. 明确资料边界：哪些来自原文，哪些不能编造。
3. 建立一个中性的核心模型。
4. 输出十类中文解释文章：
   - 第一性原理解释
   - 客户需求解释
   - 生活化类比解释
   - 历史发展解释
   - 层次化/结构化/模块化解释
   - 控制论/反馈解释
   - 信息论解释
   - 最小 Demo 解释
   - 数据结构解释（线性表、树、图）
   - 费曼式解释（讲解、暴露缺口、回源、重写、验证）
5. 全部文章写完后做四类检视：
   - 源材料忠实度检视：从原始输入逐项检查遗漏、扭曲、放大、弱化、脱离上下文和无依据增补。
   - 正向检视：从原文和核心模型出发，检查是否讲清楚、讲准确。
   - 反向检视：从文章结论倒推原文，检查是否讲过头、讲偏或编造。
   - 交叉检视：和其他文章对照，检查定义、数字、流程、边界是否一致。
6. 汇总所有文章的公共问题，统一修复。
7. 修复后重新做源材料忠实度检视和交叉检视。
8. 抽取可复用概念和未解决问题。
9. 汇总成最终输出，确认无关文件未混入后提交推送。

详细工作流见 `workflows/autodigest.md`。

## 创建一个新消化包

```bash
python3 scripts/new_digest.py "Transformer Attention"
```

脚本会生成：

- `sources/<主题>.md`
- `digests/<主题>.md`
- `concepts/<主题>.md`
- `outputs/<主题>/` 下的十篇中文文章草稿

## 消化标准

每次认真消化都要回答：

- 这个东西解决什么问题？
- 它由哪些核心部分组成？
- 这些部分如何交互？
- 最小可运行例子是什么？
- 我还有哪些地方没搞懂？
- 如果讲给低一个层次的人，应该怎么讲？

每次认真消化还必须完成：

- 整套产出的源材料忠实度检视。
- 每篇文章的正向检视。
- 每篇文章的反向检视。
- 每篇文章的交叉检视。
- 公共问题修复。
- 修复后的最终忠实度和一致性检查。
