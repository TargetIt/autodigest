# Auto Digest 提示词

使用下面提示词处理复杂材料。默认目标是先打穿一个核心解释，而不是一次性填满所有视角模板。

```text
我正在学习下面这个复杂对象：

[粘贴原文摘录、笔记、链接摘要、论文片段、文档片段或转写内容]

请使用 Auto Digest 工作流帮我消化它。

总原则：

- 默认使用中文。
- 不编造事实、历史、机制、数据、人物、名称或因果关系。
- 明确区分：原文事实、解释、类比、推测、外部补充。
- 先追求核心解释质量，再考虑多视角扩展。
- 不要为了填满模板而硬套控制论、信息论、数据结构或历史视角。
- 资料不足时，必须标注为“待确认”或“开放问题”。

第一轮只做源信息账本和理解诊断，不要写长文章：

1. 定义待消化对象。
2. 说明资料边界：哪些来自原文，哪些不能编造。
3. 把原始材料拆成带来源位置的编号信息单元，覆盖事实、主张、机制、数据、定义、例子、条件、例外、不确定性和开放问题。
4. 记录每个信息单元的原始含义、强调程度、证据强度、条件和边界，以及它是否进入核心解释。
5. 找出最难懂的 3-7 个点：跳步、术语依赖、隐含前提、边界条件、反直觉结论、容易误解处。

第二轮只写一篇核心解释：

1. 先说明这个对象解决什么问题。
2. 写出一句话理解，但不要牺牲关键条件。
3. 解释必要组成部分。
4. 按机制顺序讲清楚这些部分如何交互。
5. 给出一个具体例子。
6. 说明它不是什么，以及在哪些条件下不成立。
7. 明确哪些是原文事实，哪些是解释或推导。
8. 结尾用普通中文重建理解。

第三轮用例子、反例和追问修复核心解释：

1. 设计一个最小例子，让核心机制从输入到输出可见。
2. 给出至少一个反例或不适用场景，用来校准边界。
3. 用连续追问暴露解释中的跳步：为什么、如果条件改变会怎样、有没有新例子、哪里会失败。
4. 回到源信息账本修复跳步、术语依赖和无依据断言。
5. 重写核心解释中被修复的段落。

第四轮才选择可选视角扩展：

从下面视角中选择最能带来新增理解的 2-4 个。每个视角生成前必须先判断是否适合；不适合就说明跳过原因，不要硬写。

可选视角：

1. 第一性原理：从基础约束和原始需求一步步推导。
2. 客户需求：从用户痛点、成功标准和傻瓜式使用角度解释。
3. 生活化类比：用简单比喻解释，但必须映射回真实机制并说明边界。
4. 历史发展：只有资料支持时，解释演化过程和替代关系。
5. 层次化系统：解释层次、模块、输入、输出、功能和接口。
6. 控制论：只有存在目标、控制者或可操纵条件时，从可能性空间、控制能力和反馈解释。
7. 信息论：只有信息源、信号、通道、接受者和解释过程清晰时使用。
8. 最小 Demo：进一步扩展可运行或可观察例子。
9. 数据结构：只有对象能自然抽象为元素和关系时，分析线性表、树或图。
10. 费曼式消化：记录第一次讲解、缺口、回源修复、第二次讲解和迁移验证。

第五轮做检视：

1. 源材料忠实度检视：源信息账本中的重要信息是否进入核心解释或被主动省略，省略理由是什么。
2. 产出到源材料检视：核心解释、例子、反例和视角扩展中的新增内容是否有依据，是否正确标注。
3. 质量检视：是否真正讲清楚了核心问题、机制、例子、边界和误解。
4. 一致性检视：核心解释、最小例子、反例和可选视角之间是否矛盾。
5. 修复公共问题，保留仍然开放的问题。

最后输出：

- 源信息账本。
- 理解难点。
- 修复后的核心解释。
- 最小例子。
- 误解与反例。
- 追问修复记录。
- 被选择和被跳过的视角。
- 检视记录。
- 最终输出草稿。
```
