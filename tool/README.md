# autodigest

`autodigest` 是一个用于学习复杂概念的自动消化仓库。

它的目标不是把材料整理成一组形式完整的笔记，而是先回答「我的当前问题」，把一个知识对象真正讲清楚，再按需要扩展成文章、指南、图解或演讲稿。默认输出中文内容。

## 核心原则

- 形式少一点，思考多一点。模板只给锚点，不给表格；正文自由写作。
- 「我的当前问题」是唯一验收标准。产出多少文件都不算完成，问题被回答、人能复述并做出此前做不出的判断，才算完成。
- 核心解释没讲清之前，不做任何扩展。
- 检视的价值是发现问题并修复，不是确认「没有问题」。

一次认真消化走这条主线：

1. 输入锚定：收集对象、材料、读者、期望输出、我的当前问题、约束。缺料即停。
2. 轻量源信息账本 + 理解难点：只录会用到的、冲突的、不确定的；难点必须挂钩我的当前问题。
3. 核心解释：自由写作一篇，把问题、机制、例子和边界讲通。
4. 验收闸门：交给用户，按反馈修复，直到用户说「懂了」。到此即为最低完成。
5. 反例与追问（按需）：校准边界、暴露并修复解释缺口。
6. 视角扩展（可选）：只写能带来新增理解的，最多 2 个；跳过是默认。
7. 检视：5 条论断回源抽查 + 对抗自检 + 读者测试，写成短文。
8. 最终输出：按期望输出整理，结尾必含「我现在能做的判断/行动」。

## 仓库结构

```text
autodigest/
  inbox/       临时材料、链接、摘录、想法。
  sources/     原始材料归档（手动放入）。
  digests/     按主题分目录，每个主题 4 个文件：输入锚定、核心消化、视角扩展、检视与输出。
  concepts/    可复用概念页（消化后沉淀，不自动创建）。
  outputs/     对外发布时使用（可选）。
  prompts/     6 轮提示词模板。
  scripts/     小型本地自动化脚本。
  templates/   4 个消化文件骨架 + articles/ 下 10 个可选视角提问法（纯参考工具箱）。
  workflows/   Auto Digest 工作流。
```

## 默认消化包

创建一个新消化包：

```bash
python3 scripts/new_digest.py "Transformer Attention"
```

脚本会生成：

```text
digests/transformer-attention/
  00-输入锚定.md     对象、材料、读者、期望输出、我的当前问题、约束
  01-核心消化.md     轻量账本、理解难点、核心解释、验收回访
  02-视角扩展.md     可选，默认跳过
  03-检视与输出.md   忠实度抽查、对抗自检、读者测试、最终输出草稿
```

## 质量标准

每次消化必须回答：

- 这个东西解决什么核心问题？
- 它最容易被误解成什么？
- 它由哪些必要部分组成？这些部分怎样交互，形成什么机制？
- 最小可运行或可观察例子是什么？
- 哪个反例能说明它不是什么、何时不成立？
- 我的当前问题是否被逐条回答？没回答的有没有直说？
- 学会它以后，人的判断或行动能力发生什么变化？

每次认真消化还必须完成：

- 从核心解释挑 5 条最大胆的论断回源抽查（一致 / 变形 / 无依据）。
- 换角色攻击自己的解释至少 3 处，逐条回应。
- 回到输入锚定逐条验收我的当前问题。
- 未确认信息标注为「待确认」或「开放问题」。

## 使用建议

不要让大模型一轮生成全部内容。按 `prompts/digest.md` 的 6 轮分轮进行，核心解释完成后的用户验收轮不可跳过。这样可以避免模型为了满足模板而牺牲内容深度。

每个消化包的 4 个文件只是锚点，不是表格：除少量引导行外，全部自由写作。
