# Auto Digest 提示词模板

把下面各轮提示词按顺序使用。每轮都是一轮独立的对话；上一轮的产出和用户反馈，作为下一轮的输入粘贴进去。

总原则（硬约束）：

- 默认中文。
- 不编造事实、机制、数据、人物、名称或因果关系。
- 明确区分：原文事实、解释、类比、推导、推测、外部补充。
- 不确定就标「待确认」或「开放问题」。
- 「我的当前问题」是唯一验收标准。
- 核心解释没讲清之前不做任何扩展。

## 第 1 轮：输入锚定 + 轻量账本 + 理解难点

```text
[粘贴：待消化对象、原始材料、读者、期望输出、我的当前问题、已知约束。
若这些还没收集齐，先和用户对话收集，不要开始写作。]

请先用自己的话重述：对象是什么、读者是谁、我的当前问题是哪几条。
重述有出入，就先澄清再继续。

然后完成两件事：

1. 轻量源信息账本：把材料拆成编号条目（S1、S2…），自由列表，每条一行：

   S3 [原文位置] 类型 —— 核心含义一句话

   只录真正会用到的、冲突与限制条件的、不确定的内容，不为全而录。

2. 找出 3-7 个理解难点，说明哪里难、为什么难，并标明每个难点对应我的哪一条当前问题；
   我的问题没有对应难点的，补一个。

本轮不写解释、不写文章。
```

## 第 2 轮：核心解释

```text
[粘贴：输入锚定 + 第 1 轮产出]

动笔前重述：对象、读者、我的当前问题。

只写一篇核心解释，自由写作，允许任何文体，按这个顺序：

1. 一句话理解（含关键条件，不许牺牲条件换顺口）。
2. 它解决什么问题；没有它会遇到什么基础矛盾。
3. 机制正文（主体）：把必要部分和交互顺序讲透。
4. 一个具体例子：有具体数字、名字、可心算跑通；说明它展示什么、省略什么、为何省略不歪曲原理。
5. 它不是什么；哪些条件下不成立。
6. 普通中文重建：不看原文，用自己的话重讲一遍。

好的解释的标准（照此打磨，不要应付）：

- 复述测试：聪明但不熟悉主题的人，读完能复述机制。
- 新手测试：锚定里定义的读者每一步都跟得上。
- 无术语空转：每个关键术语都有机制解释。
- 例子具体：没有「假设有一个系统」这类占位。

可疑内容用行内标注区分（如 [推导] [类比] [原文:S3] [外部补充]）。

结尾单独一节「验收回访」，逐条回答我的当前问题：已回答 / 部分回答 / 没回答，分别直说，不许含糊。
写完就停，交给用户验收。
```

## 第 3 轮：按用户反馈修复

```text
[粘贴：第 2 轮的核心解释 + 用户的原话反馈]

用户的反馈是最高优先级。逐条处理：哪里卡住就重讲哪里，哪里错了就改哪里，
哪个问题没被回答就补回答。修复要改进正文本身，不要写「修改说明」代替修改。

修复后重新做验收回访，再交给用户。这一轮可以重复，直到用户说「懂了」。
```

## 第 4 轮：反例与追问（按需，可跳过）

```text
[粘贴：已验收的核心解释 + 输入锚定]

只在边界不清、可能被误解时做。完成：

1. 最有诱惑力的误解是什么、为什么有诱惑力、错在哪。
2. 1-2 个反例或不适用场景，校准边界。
3. 连续追问「为什么」直到卡住；记录缺口类型（跳步 / 术语依赖 / 循环定义 /
   无依据断言 / 边界缺失 / 例子不足），回源修复，把修复直接改入核心解释正文。

如果核心解释的边界已经清楚，就直说本轮跳过。
```

## 第 5 轮：视角扩展（可选，默认跳过）

```text
[粘贴：已验收的核心解释]

先回答一个问题：哪些视角能带来核心解释没有的新增理解？
答不上来就跳过，本轮结束。

最多写 2 个，每个写明「相对核心解释新增了什么」。
templates/articles/ 下的 10 个视角提问法可参考，不是必须填的模板。
```

## 第 6 轮：检视与最终输出

```text
[粘贴：核心解释 + 所有扩展 + 输入锚定]

检视写成短文，只做三件事：

1. 忠实度抽查：挑 5 条最大胆、最具体、最容易被误引用的论断，逐条回源对照
   （一致 / 变形 / 无依据），变形或无依据的修复或删除。
2. 对抗自检：「一个持不同意见的专家会从哪 3 处攻击这篇解释？」
   逐条回应：攻击成立就修复，不成立写明为什么。
3. 读者测试：逐条验收我的当前问题；预测读者会在哪里卡住，卡住的就改。

然后按「期望输出」写最终输出草稿，结尾必须包含「我现在能做的判断/行动」一段。

最后列出开放问题清单。
```
