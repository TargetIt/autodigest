# Auto Digest 工作流

当一个复杂概念、复杂系统、技术方案、产品能力或知识点需要被消化时，使用这个工作流。

目标只有一个：让「我的当前问题」被真正回答。产出多少文件、写多少视角，都不算完成；问题被回答、人能复述并做出此前做不出的判断，才算完成。

## 硬约束（不可违反）

1. 不编造事实、机制、数据、人物、名称或因果关系。
2. 明确区分：原文事实、解释、类比、推导、推测、外部补充。标注方式自定（行内 [推导] [类比] [原文:S3]，或文末说明），只要读者能分辨。
3. 不确定的内容必须标注「待确认」或「开放问题」。
4. 「我的当前问题」是唯一验收标准：核心解释写完后逐条回答它；没回答或没把握的，必须直说。
5. 核心解释没讲清楚之前，不做任何扩展（不写视角、不写输出稿）。

## 软建议（可自由取舍）

- 视角工具箱（templates/articles/ 下的 10 个视角提问法）是参考，不是任务清单。只取真正带来新增理解的，答不上来「它新增了什么」就跳过。
- 各阶段的提问清单是引导，不是表格。自由写作优先。
- 检视发现的问题，修复或明确记录为开放问题后再收尾。

## 一个消化包的完整流程

### 阶段 1：输入锚定（缺料即停）

写作前必须收集齐，缺任何一项就停下来先补：

- 待消化对象：一句话说清它是什么，边界内外。
- 原始材料：链接、路径或摘录。没有材料 → 停止，先去收集。
- 读者是谁：默认「我本人」，写下背景与前置知识。
- 期望输出：一句话——只求自己懂 / 学习笔记 / 对外文章 / 图解 / 演讲稿。
- 我的当前问题：以「我不懂 / 我总搞混 / 我想知道」开头的 1-5 个具体问题。这是验收标准。
- 已知约束：长度、风格、必须包含或回避的内容。

这六项写入 `digests/<主题>/00-输入锚定.md`。此后每个阶段动笔前，先重述这六项（对象、读者、我的当前问题至少三样），防止跑偏。

### 阶段 2：轻量源信息账本 + 理解难点

把材料拆成编号条目（S1、S2…），自由列表，不建多列表格。每条一行：

```
S3 [原文位置] 类型：事实/主张/机制/定义/例子/条件/不确定性 —— 核心含义一句话（可附原文引语）
```

只录三类：真正会被用到的、冲突与限制条件的、不确定的。不为「全」而录。

然后找 3-7 个理解难点，自由文字写「哪里难、为什么难」。每个难点必须挂钩「我的当前问题」；用户的哪个问题没有对应难点，就补一个——这一步是检查输入锚定有没有被真正理解。

### 阶段 3：核心解释（整个流程的心脏）

只写一篇，自由写作，允许任何文体。顺序建议：

1. 一句话理解（含关键条件，不许牺牲条件换顺口）。
2. 它解决什么问题；没有它会遇到什么基础矛盾。
3. 机制正文：这是绝对主体，用散文把必要部分和交互顺序讲透。
4. 一个具体例子：有具体数字、名字、可心算跑通；说明它展示什么、省略什么、为何省略不歪曲原理。
5. 它不是什么；哪些条件下不成立。
6. 普通中文重建：不看原文，用自己的话重讲一遍。

「好的核心解释」的可检验标准：

- 复述测试：一个聪明但不熟悉该主题的人，读完能不看原文复述机制。
- 新手测试：输入锚定里定义的读者，每一步都跟得上，不需要额外背景。
- 无术语空转：每个关键术语都有机制解释，不用术语回答「为什么」。
- 例子具体：没有「假设有一个系统」这类空泛占位。

### 阶段 4：验收闸门（流程里最硬的一环）

核心解释写完后必须停下来交给用户：

1. 逐条回答「我的当前问题」：回答了 / 部分回答 / 没回答，分别直说。
2. 请用户反馈：哪里还卡住、哪里讲错了、哪个问题其实没被回答。
3. 按反馈修复核心解释，再交一轮，直到用户说「懂了」。

用户验收通过 = 本次消化的最低完成。之后的阶段全部按需执行，跳过是默认，不是异常。

### 阶段 5：反例与追问（按需）

当用户反馈或检视发现「边界不清、可能误解」时才做：

- 最有诱惑力的误解是什么、为什么有诱惑力、错在哪。
- 1-2 个反例或不适用场景，校准边界。
- 连续追问「为什么」直到卡住；卡住处记录缺口类型（跳步 / 术语依赖 / 循环定义 / 无依据断言 / 边界缺失 / 例子不足），回源修复，直接把修复后的文字改入核心解释正文，不留修复记录表。

### 阶段 6：视角扩展（可选，默认跳过）

默认跳过。若某个视角能带来核心解释没有的新增理解，才写，最多 2 个。写之前必须回答「它相对核心解释新增了什么」，答不上来就跳过。跳过不需要写理由表格。

### 阶段 7：检视（不做勾选表）

检视写成短文，只做三件事：

1. 忠实度抽查：从核心解释里挑 5 条最大胆、最具体、最容易被误引用的论断，逐条回源对照，报告 一致 / 变形 / 无依据。变形或无依据的，修复或删除。
2. 对抗自检：换一个角色提问——「一个持不同意见的专家，会从哪 3 处攻击这篇解释？」逐条回应：攻击成立就修复，不成立就写明为什么。
3. 读者测试：回到输入锚定，逐条验收「我的当前问题」；预测读者会在哪里卡住，卡住的就改。

检视的价值是发现问题并修复，不是确认「没有问题」。一份没有任何发现的检视，比没有检视更可疑。

### 阶段 8：最终输出与提交

按输入锚定里的「期望输出」决定形式。结尾必须包含一段「我现在能做的判断/行动」——学会它之后，人的判断或行动能力发生了什么变化。没有这一段，理解没有落点。

若沉淀出可复用的概念，写入 `concepts/`；原始材料可归档进 `sources/`。

提交前确认：重要源信息有明确去向、未确认信息已标注、视角没有硬套、检视发现的问题已处理或记录为开放问题、只提交本次相关文件。

## 方法来源说明

控制论与信息论两个可选视角主要借鉴金观涛、华国凡《控制论与科学方法论》第一章「控制和反馈」和第二章「信息、思维和组织」，并转换成适合 Auto Digest 的提问框架。书中的「可能性空间」「共轭控制」等表述包含作者自己的方法论创造，与西方控制理论、维纳控制论或香农信息论不完全等同；使用时必须注明这是本书启发下的定性方法，不能把它们混写成所有学派一致接受的严格定义。
